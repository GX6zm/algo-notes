点分治

把一棵大树，拆成一堆小问题

一句话说清：每次挑出当前树的重心当"关卡"，只统计跨过这道关卡的路径；没跨过去的路径，一定整条躲在某一棵子树里，于是把重心删掉，对每块递归再做一遍。

图中 橙色 是重心；删掉它，树裂成三个大小相近的小块（蓝 / 绿 / 紫）。

WHAT
它解决什么
树上"路径"的计数与最值：距离 ≤ K 的点对、路径和等于 K、最长合法路径……
HOW
核心武器
树的重心：删掉它后最大连通块 ≤ 原规模的一半，保证递归只有 log n 层。
COST
代价
每层 O(n log n)，共 O(log n) 层 → 总复杂度 O(n log² n)，n = 10⁵ 也轻松跑。

01 从一道题说起02 / 问题

为什么树上的路径这么难数？

经典例题：Luogu P4178 / POJ 1741「Tree」

题目　给一棵 n ≤ 100000 个节点的树，边有正整数权值，问有多少对点 (u, v)，满足它们之间的路径长度 ≤ K？（u < v）

树上任意两点之间只有一条简单路径，所以"距离"是明确的。问题在于：路径数量是 O(n²) 级别的，直接两两枚举、逐条走一遍，复杂度 O(n²) 甚至 O(n³)，n = 10⁵ 时必然超时。

一次枚举：点 11 到点 13 的唯一路径被高亮，长度 = 1 + 1 + 2 + 3 + 1 + 2 = 10。要数清所有这样的组合，得换个思路。

关键的分类想法

随便挑一个点 c 当"关卡"，那么任意一条路径，必然属于下面两类之一：

A · 经过 c
两端点在 c 的不同子树里（或一端就是 c）。这类路径可以拆成"到 c 的距离之和"，一次性批量统计。
B · 不经过 c
整条路径完全落在 c 的某一棵子树内部。把 c 删掉，它就是一个规模更小的同类问题 → 递归！
所有路径 = 经过 c 的路径 + 各子树内部的路径（递归）
那 c 该挑谁？如果随便挑一个叶子，删掉它剩下的块还是 n−1 个点，递归 10⁵ 层，白忙一场。必须挑"最居中"的点，让每块都至少减半 —— 这就是树的重心。另外每层都要重新挑 c，所以是"分治"，不是一次 DFS。

02 核心工具：树的重心03 / 重心

重心 = 把树"切得最匀"的那个点

定义、性质、求法，一次讲清

定义

删掉点 u 后，树会裂成若干个连通块。记其中最大块的大小为 maxPart(u)。使 maxPart 最小的点，就是这棵树的重心。

性质

重心的每个连通块大小都 ≤ n / 2。所以每递归一层，规模至少减半 → 递归深度 ≤ log₂ n（n = 10⁵ 时不超过 17 层）。

13 个点的树：删掉重心 ①，得到 4 / 4 / 4 三块，最大块 4 ≤ 6.5；若改删 ②，最大块变成 9，显然不够"匀"。

怎么求：一次 DFS 就够

把当前连通块临时以任意点当根，DFS 算出每棵子树大小 sz[u]。删掉 u 后，除了它的各个子树，还有"父亲方向"那一大块，大小是 all − sz[u]（all = 当前连通块总点数）。

maxPart(u) = max( max sz[v] , all − sz[u] )　→　取最小值对应的 u
① 先算规模
getSize(entry, 0) 得到 all = sz[entry]；已被删除的重心要跳过。
② 再挑最优
DFS 时顺手更新 maxPart[u]，全程维护最小值，得到重心 root。
intuition（直觉）：想象一棵树吊在一根绳上，重心就是那个能让树平衡悬挂的点。它保证"往任意一边走，剩下的点都不会超过一半"。这就是点分治复杂度的全部秘密。

两个容易忽略的细节

  • 重心可能有两个（例如一条偶数个点的链，中间两点都合格），任选其一即可，不影响正确性与复杂度。
  • 每层都要重算：删掉旧重心后，子树的形状变了，all 也变了，必须重新 DFS 求新重心，不能沿用上层的编号。

03 点分治三步走04 / 流程

分解 → 统计 → 递归

整个算法就是这三步反复执行

1
找重心
在当前连通块里求重心 c，把它标记成"已删除"（dead[c] = true）。
▶
2
统计经过 c 的路径
收集各点到 c 的距离，用排序 + 双指针数出 d[u] + d[v] ≤ K 的对数，再扣掉同一子树内的重复。
▶
3
递归各子树
c 被删后剩下的每个连通块，各自回到第 1 步。
Ans(块) = Calc(重心 c) + Σ Ans(c 删掉后的第 i 块)

递归树示意：第 0 层 13 个点 → 第 1 层 3 块各 4 个点 → 第 2 层继续对半切……每层总点数仍是 O(n)，但层数只有 O(log n)。

为什么既不重复、也不遗漏？

疑问答案
会漏吗？任取一条路径，从最上层往下看，它要么经过当前重心（被 Calc 抓住），要么整体落在某块里（被递归抓住）。二者必居其一，所以不漏。
会重吗？一条路径第一次遇到"经过的重心"时就被统计；之后重心被删除，路径两端落入不同块，不可能再被任何一次 Calc 数到。所以恰好一次。
Calc 里的重复是什么？两个点在同一棵子树时，它们的路径根本不经过 c，但距离数组里仍会被配对。必须单独减掉（容斥），详见下一页。
最核心的一句话：点分治 = 「以重心为分界，把路径按最高经过的分界点归类」。每条路径只属于一个分界点，因此可以直接相加，不需要任何去重数据结构。

04 统计经过重心的路径05 / Calc

Calc(c)：数组、双指针与"减重复"

设 K = 6，用第 1 页那棵树、重心 ① 来走一遍

第 1 步：按子树分组，收集到重心的距离

节点旁标注的是到重心 ① 的距离 d。重心自己 d = 0。三条分支各自是一组。

蓝组（经 ②）
d = [2, 3, 4, 4]
绿组（经 ③）
d = [1, 2, 3, 5]
紫组（经 ④）
d = [3, 4, 5, 6]

第 2 步：全部放一起排序，双指针数配对

把重心 0 和所有 d 放进数组 all，排序后用左右指针 l, r：若 all[l] + all[r] ≤ K，因为后面的数不会超过 all[r]，所以 l 与 l+1…r 全都合格，一次加 r − l 对，然后 l++；否则说明右端点太大，r−−。单次 O(m log m)。

排序后的 all 数组（颜色对应所属分支）。例如 l 指向 0、r 指向 6：0 + 6 ≤ 6，说明重心与其余 12 个点全都合格，一次加 12 对。

第 3 步：容斥，把"没经过重心"的配对减掉

同组两点（比如 ⑤ 和 ⑥）的路径只在蓝组内部绕，不经过重心 ①，却被上一步算进去了。所以对每一组单独再做一次 count(组)，从总数里减去：

Calc(c) = count(all ∪ {0}) − Σ count(每一组)
伪代码 all = {0} ∪ 各组距离 → 对每组 res −= count(组) → 最后 res += count(all)。完整可编译实现见下一页。
别忘了 (重心, 某点) 这类路径：它确实经过 c，必须计入。把 0 放进 all 就能自动覆盖，不用特判。

05 完整代码06 / 实现

一份能过的 C++ 模板

对应「距离 ≤ K 的点对数」，n ≤ 10⁵，答案用 long long

const int N=100005, INF=1<<30;
struct Edge{int to,w;}; vector<Edge> g[N];
bool dead[N]; // 已删除的重心
int sz[N], maxp[N], all, best, root, K; long long ans;

// ① 算当前连通块大小
void getSize(int u,int fa){
  sz[u]=1;
  for(auto e:g[u]) if(e.to!=fa&&!dead[e.to]){ getSize(e.to,u); sz[u]+=sz[e.to]; }
}
// ② 同一个 DFS 里顺手挑重心
void findRoot(int u,int fa){
  sz[u]=1; maxp[u]=0;
  for(auto e:g[u]) if(e.to!=fa&&!dead[e.to]){
    findRoot(e.to,u); sz[u]+=sz[e.to];
    maxp[u]=max(maxp[u],sz[e.to]);
  }
  maxp[u]=max(maxp[u],all-sz[u]);        // ★ 父亲方向那一块
  if(maxp[u]<best) best=maxp[u], root=u;
}
// ③ 收集一组内所有点到重心的距离
void getDis(int u,int fa,int d,vector<int>& ds){
  ds.push_back(d);
  for(auto e:g[u]) if(e.to!=fa&&!dead[e.to]) getDis(e.to,u,d+e.w,ds);
}
// ④ 排序 + 双指针：数出和 ≤ K 的配对数
long long countPairs(vector<int> ds){
  sort(ds.begin(),ds.end()); long long res=0;
  int l=0, r=(int)ds.size()-1;
  while(l<r){ if(ds[l]+ds[r]<=K) res+=r-l,l++; else r--; }
  return res;
}
// ⑤ 统计经过重心的路径（含容斥）
long long calc(int c){
  vector<int> allv{0}; long long res=0;
  for(auto e:g[c]) if(!dead[e.to]){
    vector<int> sub; getDis(e.to,c,e.w,sub);
    res-=countPairs(sub);                  // ★ 减同组重复
    allv.insert(allv.end(),sub.begin(),sub.end());
  }
  return res+countPairs(allv);
}
// ⑥ 主流程：找重心 → 删 → 统计 → 递归
void solve(int entry){
  getSize(entry,0); all=sz[entry];   // ★ 每层重算规模
  best=INF; findRoot(entry,0);
  int c=root; dead[c]=true;          // ★ 先删再算
  ans+=calc(c);
  for(auto e:g[c]) if(!dead[e.to]) solve(e.to);
}
// main: 读 n、K 与边 → solve(1) → 输出 ans
三个 ★ 是灵魂：① all − sz[u] 补上父亲方向；② 容斥减同组；③ 每层重算 all 并先标记 dead。少一个就错。
为什么先删再统计？dead[c]=true 后，getDis 不会走回已处理的块，各块天然被隔开。

06 复杂度 · 易错点 · 应用07 / 进阶

它为什么快，以及哪里最容易翻车

复杂度推导

环节单层代价说明
找重心 / 收集距离O(m)当前块每个点恰好被访问常数次。
排序 + 双指针O(m log m)每层对若干组分别排序，总和不超过 O(m log m)。
递归层数O(log n)重心保证每块 ≤ 一半。
合计O(n log² n)每层所有块加起来是 O(n) 个点，共 log n 层。
n = 100000 时的量级对比（示意）
暴力 O(n²)
≈ 10¹⁰ 次
点分治 O(nlog²n)
≈ 3×10⁷ 次

六个高频坑

1 · 忘记 all − sz[u]
只比下方子树，会把"父亲方向"那一大块漏掉，找出的重心是错的。
2 · 忘记容斥
同一子树内的配对没减掉，答案偏大。顺序：先减各组，再加全体。
3 · 没有重算 all / sz
递归进了新块，却沿用上层的 all，重心立刻算歪。
4 · dead 标记时机
必须先 dead[c]=true 再 calc 与递归，否则 DFS 会越界回到已处理区域。
5 · 答案溢出
n = 10⁵ 时点对可达 5×10⁹，ans 与 res 都要 long long。
6 · 边权 / 距离剪枝
收集距离时若 d > K 可提前不加入数组（对 ≤ K 题型）；有 0 权或负权时不能这么做。

还能变形到哪些题

题型改造点
路径长度 恰好 = K把 countPairs 换成"和 = K"的双指针 / 桶计数，容斥不变。
求最短合法路径 / 最长合法路径维护分组最小距离，用桶或数组打标记，不必排序。
路径上颜色数、点权和等约束收集距离时附带额外状态，用桶或哈希表统计。
带修改（换颜色 / 改点权）动态点分治：把分解结构建成"点分树"，每个重心挂数据结构维护子树信息。
提速一个小技巧：若 K 不大，用桶数组代替排序，每层可降到 O(m)，总复杂度 O(n log n)。竞赛里更常见的仍是 O(n log² n) 写法，简单且够快。

07 一页纸速查08 / 小结

记住这四句话就够了

① 分界

每层选重心，让最大子树 ≤ n/2，递归深度锁死在 log n。

② 归类

路径要么经过重心、要么整条落在某个子树里，二者必居其一。

③ 统计

距离数组排序 + 双指针，全体减去各组（容斥），去掉不经过重心的配对。

④ 递归

标记 dead[c] 后，对每个剩余连通块重来一遍，直到块为空。

流程速查表

步骤做什么对应代码
算规模DFS 求当前块大小 allgetSize(entry, 0); all = sz[entry]
找重心比较 max(sz[v], all−sz[u])findRoot(entry, 0)
删重心切断，形成若干独立块dead[root] = true
统计分组收集距离 → 容斥计数ans += calc(root)
递归对每个未删除的邻居块调用for e : g[root] solve(e.to)

自测三问（答案在右下）

  1. 为什么一定要用重心，随便选一个点当根不行吗？
  2. calc 里为什么要"先减各组、再加全体"？如果只算全体会怎样？
  3. 一条路径在第 1 层被统计过，到了第 2 层为什么不会又被数一次？
参考答案
1　随便选点可能只切掉 1 个点，递归 O(n) 层退化；重心保证减半，层数 O(log n)。
2　全体配对里混进了"同组两点"，它们的路径不经过重心，属于要交给递归处理的那一类；只算全体会重复计数且答案偏大。
3　重心被删除后，路径两端落在不同块，之后任何一层的 calc 都只看得见同一块内的点，不可能再凑成这条路径。
